    Terraform state backend

    Exactly one backend is selected here, and it drives both the rendered backend.tf and which bootstrap steps run. This is the decision point that resolves the current repository’s split-brain between Terraform Cloud and azurerm.

    Free tier is capped at 500 managed resources

    HCP Terraform’s legacy free plan ended 31 March 2026. The current free tier allows 500 managed resources, unlimited users, and one policy set of up to five policies. Paid tiers bill on the peak hourly count of resources in state, starting at $0.10 per resource per month.

    A managed resource is any resource in state with mode = "managed". null_resource and terraform_data are excluded. Data sources are not billed. Note that individually-declared items — each policy assignment, each role assignment, each subnet, each diagnostic setting — counts separately, which is what pushes landing zones over the cap.

    Deployment strategy

    Whether this tenant is empty or already has resources that must be adopted.

    Brownfield is read-only until you say otherwise

    Discovery never writes. Import blocks and commands are generated for review, and the destroy-protection workflow fails any plan containing a destroy or replace action unless it carries the approved-destroy label. A discovery run that lacks read permission reports forbidden, never an empty inventory — an empty result and a blocked result must never look alike.

    Defaults to Ignore so adoption is always a deliberate act.

    Deployment identities

    Both models keep the plan/apply privilege split: the plan identity only ever holds the read-only pull_request subject, and every apply credential is pinned to an environment:<name> subject. Per-environment adds blast-radius isolation between environments at the cost of a larger identity estate.

    Security services

    Microsoft Defender for Cloud

    Available, not auto-deployed: the defender-baseline module

    The module is implemented, but no terraform/live layer calls it and the renderer does not wire it in. Enabling this records the intent and lists it as an unmet dependency in CONFIGURATION.md; actually deploying Defender is a deliberate follow-up step in the generated repository, not something the first apply does for you.

    Defender plans are billed per resource per month and are the largest single cost lever in a landing zone. Enable deliberately.

    Microsoft Sentinel

    Blocked: the sentinel-siem module is scaffold-only

    That module currently declares zero resources. Rather than emit a configuration that silently does nothing, the renderer rejects this until the module is implemented. You can select it to record the intent; the readiness report will list it as an unmet dependency.

    Key Vault

    Blocked: the keyvault-cmk module is scaffold-only

    Same situation as Sentinel — the module exists but declares no resources. Selecting this records the intent and surfaces it as an unmet dependency rather than producing a no-op.
