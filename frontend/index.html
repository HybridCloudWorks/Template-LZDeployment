Azure Landing Zone .tfvars Generator

Deprecated. The Landing Zone Factory wizard (site/) is the only supported path: it asks every landing-zone question and exports the full lz-config.json artifact set the generator consumes. This page predates the factory; the tfvars it emits target the retired self-deploy pipeline (removed by ADR 0013) and are not consumed by the AVM generator. It is kept for reference only. See frontend/README.md.

1. Organization & Location

Display name, used only in the generated file headers
2–10 lowercase alphanumeric characters — must satisfy the org_prefix validation in terraform/live/global/variables.tf
Feeds primary_region / primary_region_code in the connectivity layer
Feeds dr_region / dr_region_code (auto-paired with primary, editable)
Added to allowed_locations only (no extra hubs are deployed)

2. Network Architecture

Emitted as firewall_type = "azfw" with the chosen azfw_tier. Palo Alto / Fortinet NVA options exist in Terraform but are not offered here — use the site/ wizard.

3. Monitoring & Security

None of the toggles below is connected to a terraform/live/* call today, so none is emitted. They are shown to preserve roadmap intent.

4. Azure Policy — what this repository actually enforces

Reconciled against terraform/modules/policy-baseline/. Enforced policies deploy unconditionally with the global layer; there is no per-policy variable, so no policy selection is written to the generated .tfvars.

5. Management Group Customization not consumed — nothing emitted

The management-groups module derives all management group names from org_prefix; there is no variable to override individual names. Custom names entered here would go nowhere, so the fields are disabled.

6. Resource Naming informational only — nothing emitted

CAF-style naming is fixed inside the Terraform modules and derived from org_prefix, environment, and region code. There is no naming variable to configure. Examples with your Organization ID:

Storage Account: st[prefix]prod001
Virtual Machine: vm-[prefix]-prod-001
Virtual Network: vnet-[prefix]-prod
Resource Group: rg-[prefix]-prod-westus

7. Network Configuration (CIDR Blocks)

Address space for the primary hub virtual network
Belongs to a different layer: the first entry is emitted as a comment for hand-copy into terraform/live/workloads-prod (primary_spoke_address_space). Additional lines are not consumed by any stack.

8. Default Tags (default_tags)

Emitted into the connectivity layer’s default_tags. The require-mandatory-tags policy (always enforced at root) denies resources missing owner, application, environment, or cost_center tags.

e.g. prod
Team or person responsible for resources
For cost allocation and billing
Application or workload identifier

9. Review & Generate

Generates two files: terraform.auto.tfvars (global layer) and connectivity.auto.tfvars (platform-connectivity layer). Subscription IDs, management_ip_ranges, and the Log Analytics workspace ID are emitted as commented placeholders you fill by hand — see README.md.
